# ร้านสานะกิมหยง — ระบบขายสินค้าออนไลน์และหน้าร้าน

ระบบจัดการร้านค้าที่เชื่อมการขายออนไลน์ การขายหน้าร้าน สินค้า และ Stock เข้าด้วยกัน รองรับผู้ใช้งาน 3 กลุ่ม ได้แก่ **Admin**, **Employee** และ **User** พร้อมระบบ QR สินค้า ประวัติ Stock และรายงานยอดขาย/กำไร

หน้าเว็บไซต์ใช้ PHP เชื่อมต่อ MariaDB และรันผ่าน Docker โดยไม่ต้องติดตั้ง XAMPP

## เริ่มต้นใช้งานด้วย Docker

### สิ่งที่ต้องมี

- Docker Desktop ที่เปิดใช้งาน **Linux containers** และ Docker Engine พร้อมทำงาน
- เว็บเบราว์เซอร์
- อินเทอร์เน็ตสำหรับดาวน์โหลด Docker images ในครั้งแรก

Python และ Node.js จำเป็นเฉพาะการทดสอบหรือสร้างแผนภาพใหม่ ไม่จำเป็นสำหรับรันเว็บผ่าน Docker

### วิธีรัน

1. เปิด Docker Desktop และรอให้ Engine พร้อมใช้งาน
2. เปิด Terminal ในโฟลเดอร์โปรเจ็กต์ที่มี `compose.yaml`
3. รันคำสั่ง:

   ```powershell
   docker compose up -d --build
   ```

4. เปิดเว็บไซต์ที่ **http://localhost:8000/**
5. เปิด phpMyAdmin ที่ **http://localhost:8081/** หากต้องการดูฐานข้อมูล

เมื่อสร้างฐานข้อมูลครั้งแรก ระบบจะนำเข้าไฟล์ตามลำดับ:

1. `DB/sanahstore.sql` — ข้อมูลและตารางเดิม
2. `DB/02-roles-pos.sql` — เพิ่ม Role พนักงาน ราคาทุน POS ประวัติ Stock และส่วนประกอบใหม่

ข้อมูลฐานข้อมูลเก็บใน Docker volume ชื่อ `db_data` จึงยังอยู่หลังหยุด Container ด้วย `docker compose down` ส่วนไฟล์ PHP ถูกเชื่อมจากโฟลเดอร์โปรเจ็กต์โดยตรง แก้ไฟล์แล้วรีเฟรชหน้าเว็บได้โดยไม่ต้อง Build ใหม่

## การตั้งค่าร้านก่อนใช้งาน

ให้ Admin ดำเนินการดังนี้:

1. เข้า **จัดการสินค้า** ที่ `/admin/products.php` ตรวจราคาขาย ราคาทุน จำนวน Stock รูป และประเภทสินค้า
2. กำหนดเกณฑ์สินค้าใกล้หมด ค่าเริ่มต้นคือ **Stock ≤ 5** และปรับแยกแต่ละสินค้าได้
3. เข้า **ตั้งค่าการชำระเงิน** ที่ `/admin/settings.php` กรอกข้อมูลบัญชีธนาคารและอัปโหลด QR รับเงินจริงของร้าน
4. เข้า **ผู้ใช้งาน / พนักงาน** ที่ `/admin/users.php` เพิ่มบัญชีพนักงาน เลือก Role `Employee` และตั้งรหัสผ่าน
5. เข้า **QR สินค้า** ที่ `/admin/qr.php` เพื่อดูและพิมพ์ฉลาก

หากสินค้าไม่มีราคาทุน ระบบยังขายได้ แต่รายงานจะแสดงว่าข้อมูลต้นทุนไม่ครบ รูปสินค้าและสลิปรองรับ JPG, PNG และ WebP ขนาดไม่เกิน **5 MB**

## การขายและจัดการ Stock

### ขายออนไลน์

ลูกค้าเลือกสินค้า → เพิ่มตะกร้า → ปรับจำนวน → กรอกที่อยู่และเบอร์โทร → เลือกโอนหรือ QR Payment → ยืนยันออเดอร์ → ชำระเงินและแนบสลิป → ร้านตรวจรับเงิน → จัดเตรียมและจัดส่ง

- การเพิ่มตะกร้า **ยังไม่ตัด Stock**
- ตอนยืนยันออเดอร์ ระบบตรวจสินค้าและราคาจากฐานข้อมูลอีกครั้ง จากนั้นตัด Stock และบันทึกออเดอร์ใน Transaction เดียวกัน
- ถ้าข้อมูลผิด สินค้าปิดขาย หรือ Stock ไม่พอ ระบบยกเลิกการบันทึกทั้งหมด
- ลูกค้าดูได้เฉพาะออเดอร์ของตัวเอง

### ขายหน้าร้าน

Admin หรือ Employee เปิด `/admin/pos.php` หรือ `/employee/pos.php` แล้วค้นหาสินค้า/สแกน QR เลือกจำนวน เลือกเงินสด โอน หรือ QR Payment และยืนยันเมื่อได้รับเงินแล้ว

ระบบดึงราคาขายจากฐานข้อมูล บันทึก `pos_sales` และ `pos_items` เก็บราคาทุน ณ เวลาขาย และตัด Stock ภายใน Transaction การขาย POS ที่ยืนยันแล้วมีสถานะ `Completed`

Admin แก้ไขการขายเดิมได้ ระบบจะคืน Stock ของรายการเดิมและตัด Stock ของรายการใหม่พร้อมกัน หากรายการใหม่ไม่ผ่าน ระบบ Rollback กลับเป็นรายการเดิม การแก้รายการขายคำนวณใหม่ด้วยราคาสินค้าปัจจุบัน

### ประวัติ Stock

การรับสินค้า การปรับยอดโดย Admin การขายออนไลน์ การขาย POS และการคืนสินค้าจากออเดอร์ยกเลิกจะบันทึกประวัติ ได้แก่:

- สินค้าและผู้ทำรายการ
- จำนวนเพิ่ม/ลด และยอดคงเหลือหลังปรับ
- เหตุผลและรายการอ้างอิง
- วันที่และเวลา

ดูได้จาก `/admin/stock_history.php` หรือ `/employee/stock_history.php` เมื่อยกเลิกออเดอร์ ระบบคืน Stock **เพียงครั้งเดียว** ส่วนการลบสินค้าผ่านหน้าจัดการเป็นการปิดขาย เพื่อเก็บประวัติออเดอร์และรายการขายไว้

## สถานะคำสั่งซื้อออนไลน์

```text
รอดำเนินการ → กำลังจัดเตรียม → จัดส่งแล้ว → สำเร็จ
     ↓               ↓
   ยกเลิก          ยกเลิก
```

| สถานะ | ค่าในฐานข้อมูล | การทำงาน |
|---|---|---|
| รอดำเนินการ | `Order Placed` | สร้างออเดอร์และตัด Stock แล้ว |
| กำลังจัดเตรียม | `Order Processing` | เจ้าหน้าที่เริ่มเตรียมสินค้า |
| จัดส่งแล้ว | `Shipped` | ต้องยืนยันการชำระเงินก่อน |
| สำเร็จ | `Completed` | ลูกค้ายืนยันรับสินค้า หรือเจ้าหน้าที่ปิดงาน |
| ยกเลิก | `Cancelled` | คืน Stock และปิดออเดอร์ |

ลูกค้ายกเลิกได้เมื่อออเดอร์ยังรอดำเนินการ ส่วน Admin/Employee ยกเลิกได้ในขั้นรอดำเนินการหรือกำลังจัดเตรียม ออเดอร์สำเร็จและยกเลิกแล้วไม่สามารถย้อนสถานะ

**แนบสลิปไม่ได้หมายความว่าชำระแล้ว** ร้านต้องตรวจและเปลี่ยน `payment_status` จาก `unverified` เป็น `paid` การตรวจเงินทำโดยเจ้าหน้าที่ ไม่ได้เชื่อมยืนยันยอดกับธนาคารอัตโนมัติ สลิปเปิดได้เฉพาะเจ้าของออเดอร์หรือ Admin/Employee ผ่าน `slip.php`

## QR สินค้าและ QR ชำระเงิน

| ประเภท | หน้าที่ |
|---|---|
| QR สินค้า | ผูกกับ `product_id` ลูกค้าสแกนเปิดรายละเอียด พนักงานสแกนเพิ่มรายการ POS |
| QR Payment | ภาพ QR รับเงินที่ Admin อัปโหลดในหน้าตั้งค่าร้าน |

QR สินค้าสร้างจาก URL ของเว็บที่กำลังเปิดอยู่ เช่น `/product_content.php?id=39` การอ่าน QR รองรับกล้อง เครื่องสแกนที่ส่งข้อความแล้วกด Enter และการกรอกรหัสสินค้าด้วยตัวเอง

การใช้กล้องต้องอนุญาตสิทธิ์และเปิดเว็บผ่าน **HTTPS หรือ localhost** ค่า Compose ปัจจุบันเปิดพอร์ตเฉพาะเครื่องนี้ หากต้องการสแกนจากมือถือ ต้องจัดให้เว็บเข้าถึงผ่านเครือข่าย/HTTPS และพิมพ์ QR จาก URL ที่มือถือเข้าถึงได้ เพราะ `localhost` บนมือถือหมายถึงตัวมือถือเอง

## รายงานยอดขายและกำไร

Admin เปิดรายงานได้ที่ `/admin/reports.php` รองรับกรองวันที่ รวมยอดออนไลน์และหน้าร้าน รายวัน สินค้าขายดี ต้นทุน กำไร และ Stock ตามวันที่ พร้อมพิมพ์หรือบันทึกเป็น PDF ผ่านเบราว์เซอร์

หลักการคำนวณ:

```text
ยอดขาย = ผลรวมยอดของรายการที่สำเร็จ
ต้นทุนสินค้า = จำนวนขาย × ราคาทุนต่อชิ้นที่บันทึกตอนขาย
กำไรจากสินค้า = จำนวนขาย × (ราคาขายต่อชิ้น − ราคาทุนต่อชิ้น)
```

- รายงานนับเฉพาะรายการ `Completed` ตามวันที่ออเดอร์หรือวันที่สร้างการขาย POS
- การเปลี่ยนราคาสินค้าไม่ย้อนแก้ราคาที่เก็บในรายการขายเดิม
- ข้อมูลเดิมที่ไม่มีต้นทุนแสดงว่า **ไม่ทราบ** และไม่นับรวมในกำไรที่ทราบ
- กำไรเป็นส่วนต่างจากสินค้า ยังไม่ได้หักค่าเช่า ค่าแรง หรือค่าใช้จ่ายดำเนินงานอื่น
- รายงาน Stock ใช้ยอดจากประวัติถึงวันสิ้นสุดที่เลือก วันที่ก่อนเริ่มบันทึกประวัติจะแสดงว่าไม่มีประวัติ
- มูลค่าสินค้าคงเหลือใช้จำนวนตามรายงานคูณ **ราคาทุนปัจจุบัน** ไม่ใช่ราคาทุนย้อนหลัง ณ วันนั้น

## ฐานข้อมูลและ phpMyAdmin

เปิด **http://localhost:8081/** และเลือกฐานข้อมูล `sanahstore`

| บัญชีฐานข้อมูล | Username | Password |
|---|---|---|
| บัญชีของแอป | `sanah` | `sanah_local` |
| ผู้ดูแลฐานข้อมูล | `root` | `root_local` |

บัญชีฐานข้อมูลเป็นคนละส่วนกับบัญชีล็อกอินเว็บไซต์ ค่าข้างต้นเป็นค่าของสภาพแวดล้อมพัฒนาใน `compose.yaml`

เปิด MariaDB ผ่าน Terminal ได้ด้วย:

```powershell
docker compose exec db mariadb -u sanah -p sanahstore
```

กรอกรหัส `sanah_local` จากนั้นใช้คำสั่งตัวอย่าง:

```sql
SHOW TABLES;
SELECT product_id, product_name, stock FROM products LIMIT 20;
SELECT user_id, email, role, is_active FROM userdata LIMIT 20;
exit;
```

### อัปเกรดฐานข้อมูลเดิม

เครื่องปัจจุบันได้รัน Migration แล้ว สำหรับฐานข้อมูลเดิมบนเครื่องอื่น ให้ใช้:

```powershell
docker compose exec -T web php DB/migrate.php
```

Migration เพิ่ม/ปรับโครงสร้างโดยเก็บข้อมูลเดิม และรันซ้ำได้ การเปลี่ยนไฟล์ SQL เริ่มต้นไม่อัปเดต Docker volume ที่มีข้อมูลอยู่แล้วโดยอัตโนมัติ

## คำสั่ง Docker ที่ใช้บ่อย

ตรวจสถานะบริการ:

```powershell
docker compose ps
```

ดู Log ทั้งระบบ หรือเฉพาะเว็บ:

```powershell
docker compose logs -f
docker compose logs -f web
```

หยุดระบบโดยเก็บฐานข้อมูลไว้:

```powershell
docker compose down
```

เริ่มระบบอีกครั้ง:

```powershell
docker compose up -d
```

หลังแก้ Dockerfile ให้ Build ใหม่:

```powershell
docker compose up -d --build
```

### ล้างฐานข้อมูลและเริ่มใหม่

**คำสั่งนี้ลบข้อมูลในฐานข้อมูลของ Docker volume รวมถึงบัญชีและรายการขายที่เพิ่มภายหลัง** การเริ่มครั้งถัดไปจะนำเข้า SQL ต้นฉบับใหม่ ใช้เมื่อยอมรับการสูญเสียข้อมูลดังกล่าวแล้วเท่านั้น

```powershell
docker compose down -v
docker compose up -d --build
```

## การทดสอบระบบ

เปิด Docker ให้ระบบทำงานก่อนรันทดสอบ ชุดทดสอบสร้างบัญชีและสินค้าชั่วคราว แล้วลบเฉพาะข้อมูลของชุดทดสอบเมื่อเสร็จ ควรรันแต่ละชุดตามลำดับ เพราะใช้ไฟล์ข้อมูลทดสอบร่วมกัน

### ทดสอบการทำงานและสิทธิ์

ต้องมี Python:

```powershell
python tests/integration.py
```

ครอบคลุม Role การขาย ราคาจากเซิร์ฟเวอร์ การขายพร้อมกัน การตัด/คืน Stock ออเดอร์ การดูสลิป ความคิดเห็น รหัสผ่าน และการระงับบัญชี

### ทดสอบ UI และ QR

ต้องมี Node.js/npm และ Google Chrome:

```powershell
cd tests
npm ci
npm run browser
```

ทดสอบหน้าจอเดสก์ท็อป/มือถือ การอ่าน QR กล้องจำลอง และข้อมูลที่แต่ละ Role มองเห็น ภาพหน้าจอบันทึกใน `tests/artifacts/`

### ทดสอบการนำเข้าฐานข้อมูลใหม่

รันจากโฟลเดอร์หลักของโปรเจ็กต์:

```powershell
docker compose exec -T web php tests/fresh-schema.php
```

ชุดนี้สร้างฐานข้อมูลชั่วคราวแยกจากฐานข้อมูลร้าน ทดสอบนำเข้า SQL และ Migration ซ้ำ แล้วลบฐานข้อมูลชั่วคราวเมื่อเสร็จ ค่าบัญชีฐานข้อมูลที่ใช้ในสคริปต์อ้างอิง Compose ของโปรเจ็กต์นี้

## แผนภาพการทำงานของระบบ

เปิด **http://localhost:8000/docs/flow/index.html** เพื่อดูแผนภาพ 14 ชุด ขยายภาพ พิมพ์เป็น PDF หรือดาวน์โหลด SVG แต่ละภาพ หน้าแผนภาพเปิดเป็นไฟล์ออฟไลน์ได้ด้วย

คำอธิบายพร้อมตารางสิทธิ์ ความสัมพันธ์ข้อมูล และตัวอย่างคำนวณอยู่ใน [SYSTEM_FLOW.md](SYSTEM_FLOW.md)

หากต้องการสร้างแผนภาพใหม่หลังแก้เอกสาร ให้ติดตั้ง dependencies ใน `tests/` แล้วรันจากโฟลเดอร์หลัก:

```powershell
node tests/render-flow.cjs
```

การสร้างแผนภาพใช้ Chrome แบบ headless และโหลด Mermaid ผ่านอินเทอร์เน็ต ส่วนไฟล์ HTML/SVG ที่สร้างเสร็จเปิดดูได้โดยไม่ต้องเชื่อมต่ออินเทอร์เน็ต

## แก้ปัญหาเบื้องต้น

| อาการ | วิธีตรวจสอบ |
|---|---|
| เชื่อมต่อ Docker Engine ไม่ได้ | เปิด Docker Desktop และรอ Engine พร้อมทำงาน |
| เข้าเว็บไม่ได้ | ตรวจ `docker compose ps` และ Log ของ `web`/`db` |
| พอร์ต 8000 หรือ 8081 ถูกใช้อยู่ | เปลี่ยนพอร์ตด้านซ้ายใน `compose.yaml` แล้วรัน `docker compose up -d` |
| ไม่พบตารางหรือคอลัมน์ที่เพิ่มใหม่ | รัน `docker compose exec -T web php DB/migrate.php` |
| Employee หรือ User เข้า Admin แล้วได้ 403 | ใช้บัญชี Role Admin หรือใช้หน้าที่ตรงกับ Role |
| รายงานกำไรแสดงต้นทุนไม่ทราบ | กรอกราคาทุนก่อนขาย รายการเก่าไม่ได้เติมต้นทุนย้อนหลังอัตโนมัติ |
| เปลี่ยนเป็นจัดส่งแล้วไม่ได้ | ต้องอยู่สถานะกำลังจัดเตรียม และยืนยันรับเงินแล้ว |
| เปิดกล้องสแกนไม่ได้ | ตรวจสิทธิ์กล้อง ใช้ HTTPS หรือ localhost หรือกรอกรหัสสินค้าแทน |
| สแกนจากมือถือแล้วเปิด localhost ไม่ได้ | ใช้ URL ของเว็บที่มือถือเข้าถึงได้ และพิมพ์ QR จาก URL นั้น |
| เปิดไฟล์สลิปตรง ๆ แล้วได้ 403 | เปิดหลักฐานจากหน้าออเดอร์ผ่านบัญชีที่มีสิทธิ์ |
| แก้ PHP แล้วหน้าเว็บไม่เปลี่ยน | ตรวจว่าแก้ในโฟลเดอร์ที่ Compose เชื่อมไว้ แล้วรีเฟรชหน้าเว็บ |
